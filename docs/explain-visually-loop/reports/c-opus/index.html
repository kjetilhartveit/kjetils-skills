Oxlint, oxfmt or Biome

fantasy-snooker · ESLint + Prettier → Oxc or Biome

Switch to Oxlint + oxfmt: lint 44.0 s → 5.3 s, with 1 rule switched off and 3 path checks to port

There is no "oxprettier": Oxc's linter is oxlint and its formatter is oxfmt (beta); Biome, the all-in-one alternative, is faster still but keeps only 163 of 295 rules.

Format check: Prettier 10.2 s → oxfmt 2.3 s Output vs Prettier: oxfmt 3 code files differ, Biome 25 Decide start with oxfmt only, or the full Oxlint swap? Either way, nothing checks formatting in CI today.

2Story · 6 steps

What carries over, and what does not

Today: ESLint, the linter, takes 44.0 s on a clean run, and Prettier, the formatter, is checked by nobody: 149 files already drift from it.
Oxlint, Oxc's Rust linter, reads our ESLint config. 263 of the 276 rules it recognises migrate, including the type-aware no-unsafe-* family through tsgolint, Oxc's type-checking helper.
Biome is one package that lints and formats. Its migrator found 295 rules; 152 stable and 11 nursery (Biome's unstable) rules, 163 in all, migrate.
The rest of Biome's list is gone: 98 rules are not implemented (type-aware no-unsafe-*, React Compiler rules) and 34 come from plugins it does not know, including testing-library and our two local rules.
Oxlint's catch: 13 rules skipped, one react-x rule must be switched off because JS plugins (Oxc's alpha way to run ESLint plugins) get no type information, and 3 path checks are lost until ported.
First step: swap Prettier for oxfmt and keep ESLint. It is the lowest-risk change and the lint half can follow.

3Decision · 3 options

Which way to go

Pick how much of the toolchain to move now; the effort figures are estimates, the rule and timing numbers were measured once on one machine.

What would change this
  • JS plugins gain type information, or react-x gets native Oxlint rules: A's main gap closes
  • Biome implements no-unsafe-* and the React Compiler rules, or honours eslint-disable: B becomes viable
  • ESLint with a warm --cache is fast enough day to day (unmeasured): lint speed stops mattering, so C is enough

A · Oxlint + oxfmt

Keeps
  • 263 rules, incl. the type-aware no-unsafe-* family via tsgolint (Oxc's type-checking helper)
  • Both local/* rules, unchanged through a 2-line shim
  • All eslint-disable comments honoured (5 turn out unused)
  • Tailwind class sorting is built into oxfmt, which also formats Markdown and YAML
Loses
  • react-x/no-leaked-conditional-rendering: crashed on 190 files, must be switched off
  • 3 path checks (vi.mock, require, import() types) until ported; Oxlint prints its default message
  • Bulk suppressions: lint:baseline goes, but eslint-suppressions.json is already {}
Fix first
  • Hand-fix the migrated config: drop the includeRoles option Oxlint rejects, pin react.version to 19.2.6, re-add the test/e2e/** testing-library ignore (unsupported inside overrides); on Windows set OXLINT_TSGOLINT_PATH
  • Port the 3 lost selectors into the local plugin as a small rule
  • Add .gitattributes pinning LF, then one format commit
Risks
  • JS plugins are alpha: pin exact versions; oxfmt is beta
  • tsgolint runs on TypeScript 7 (repo: 6.0.3): 1 new no-unsafe-argument that tsc does not report
  • 1 new import/no-named-as-default-member, since import/resolver is not migrated
Effort
~1–2 days (estimate): config fixes, one small rule, .gitattributes, scripts, CI, VS Code and AGENTS.md updates, one format commit

B · Biome

Keeps
  • 163 of 295 rules (55 %): 152 stable and 11 nursery (Biome's unstable rules)
  • One package, one config; lint 3.3 s and format 0.6 s (format run was partial, CRLF errors)
  • Some type-aware rules through its own inference, without tsc
Loses
  • 98 rules not implemented: 17 typescript-eslint incl. no-unsafe-*, 14 react-hooks incl. React Compiler rules, 33 react-x, 15 react, 8 import
  • 34 rules from unknown plugins: testing-library 22, @next 10, both local/*
  • Tailwind sorting only as a nursery rule with an unsafe fix; Markdown and YAML not formatted
Fix first
  • Rewrite ~203 eslint-disable comments as // biome-ignore …: reason
  • Hand-strip eslint.config.mts to .mjs: the migrator cannot read it
  • Correct quoteStyle and semicolons written by biome migrate prettier
  • Try GritQL (Biome's plugin language) for the custom rules: not proven possible
Risks
  • 25 code files format differently from Prettier (+92/−58 lines)
  • Custom rules may have no equivalent at all
Effort
~3–5 days (estimate): rewrite disables, fix migrator output, GritQL attempts

C · oxfmt only, keep ESLint

Keeps
  • Every ESLint rule, plugin and custom rule
  • Tailwind sorting built in; 3 code files differ from Prettier output (9 files in all, the rest Markdown and HTML)
Loses
  • No lint speed-up: 44.0 s without cache (a warm --cache was not measured)
  • Two toolchains remain: ESLint plus Oxc
Fix first
  • Write .oxfmtrc.json: the migration drops endOfLine: "auto"
  • Add .gitattributes pinning LF, or oxfmt flags 1,028 files on the CRLF checkout
  • Add a format:check script to CI and pre-push; one format commit
Risks
  • oxfmt is beta
  • scripts/dev/compareNextBuilds.ts still imports prettier
Effort
~half a day (estimate): .oxfmtrc.json, .gitattributes, format scripts, one format commit

How it was measured

  • One machine (Windows 11, Node 24.21.0, 16 threads), single runs, on a git archive scratch copy of f0e33eb0.
  • Versions: ESLint 9.39.4, oxlint 1.87.0, oxlint-tsgolint 7.0.2004, oxfmt 0.72.0, Biome 2.5.15, Prettier 3.8.3.
  • ESLint: eslint . --max-warnings=0 without cache, 44.0 s. Oxlint: --type-aware 5.3 s with 4 problems, after dropping the typed react-x rule (first run crashed at 17.4 s).
  • Biome lint ran on the migrated config and ignores eslint-disable comments: 246 errors and 159 warnings.
  • A second run on the same machine gave ESLint 47.3 s and Oxlint 4.75–4.92 s. Rule counts are not comparable across migrators (276 vs 295).
  • Not measured: ESLint with a warm --cache, and the effort figures (estimates).
